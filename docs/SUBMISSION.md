## Submission Is Not a Git Push

- **GitHub:** Stores the project code and documentation.
- **Hackathon registration:** Enters the team into the competition.
- **Final project submission:** Sends the team's artefacts through the organiser's submission workflow.
- Completing one does not automatically complete the others.

## Practical Workflow

This is a preparation sequence, not a verified button-by-button walkthrough of the authenticated portal.

1. The agreed captain checks the team registration and all five member details.
2. Open the event website and follow its current team/project submission instructions.
3. Prepare the project title, track, summary, repository link, deck, and demonstration evidence.
4. Open the actual submission form and verify every required field, format, and limit.
5. Save the draft if supported; preview files and test links from another browser/session.
6. Have the team approve the package, then complete the final submit action.
7. Save the confirmation/status and a private screenshot. A saved draft is not submission evidence.

## Recommended Package

- Working prototype and reproducible setup instructions.
- Concise pitch deck covering problem evidence, solution, Google architecture, agent integration, tests, and limitations.
- Accessible demo link or recording, even if the final form makes it optional.
- Exact submitted commit SHA; no credentials or private student data.
- The documentation currently in this repository is a starting plan, not the completed prototype submission.
